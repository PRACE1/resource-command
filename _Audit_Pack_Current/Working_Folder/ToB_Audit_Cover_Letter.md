## 1. Protocol Architecture Summary

### 1.1 Zero-Knowledge Compliance Circuit

The compliance circuit is implemented in **Circom 2.2.3** targeting a **Groth16 proof system over the BN254 (Alt_BN128) scalar field**. The circuit encodes the following fiscal logic: given private production data (volume, density, ore grade), prove that the declared royalty payment is arithmetically correct under Zambia's statutory 6% open-cast copper royalty rate, without revealing the underlying production figures to the verifier.

The circuit architecture is as follows:

**Constraint 0 — Truth Anchor Binding:**  
A **Poseidon(2)** hash (circomlib implementation) commits the private volume witness to an externally pre-posted `volume_commitment_hash`. This hash is generated by an independent multi-sensor oracle pipeline (Sentinel-1 PS-InSAR fused with UAV LiDAR cross-verification) and posted to the ledger by the AfDB and World Bank validator nodes prior to the operator's declaration window. This sequencing enforces the commit-then-prove invariant and prevents input substitution by the operator.

**Constraints 1–4 — Fixed-Point Fiscal Arithmetic:**  
All real-valued inputs (volume in m³, density in t/m³, ore grade as a fraction) are encoded as fixed-point integers scaled by $10^6$. The circuit implements three scaling gates, each with an explicit remainder witness:

```
(volume_v × density_d)              = (tonnage_t        × 10⁶) + rem_tonnage
(tonnage_t × grade_g)               = (mineral_content_m × 10⁶) + rem_mineral  
(mineral_content_m × royalty_rate_bps) = (tax_paid_usd  × 10⁴) + rem_royalty
```

`royalty_rate_bps` is a public input (not a hardcoded constant), allowing the ZRA to update the statutory rate via governance without circuit redeployment. The circuit enforces that `royalty_rate_bps > 0` via `GreaterThan(13)`. Remainder witnesses are bounded via `LessThan` components: `[0, 10⁶)` for tonnage and mineral remainders; `[0, 10⁴)` for the royalty remainder.

**Input Sanitisation:**  
Private inputs use physics-derived bit widths rather than blanket `Num2Bits(64)`: `volume_v` → 40 bits (max 10¹² m³), `density_d` → 26 bits (max ~67 t/m³), `grade_g` → 20 bits (max 1,000,000 representing 100% grade). An additional `LessThan(20)` semantic bound enforces `grade_g ≤ 1,000,000`. Intermediate derived signals `tonnage_t` and `mineral_content_m` are each bounded by independent `Num2Bits(47)` components. All intermediate products remain within the BN254 scalar field (max product ≈ 2⁶⁷ ≪ p).

**Validator Infrastructure:**  
The verifier is deployed across a five-node permissioned BFT network (n=5, f=1) comprising the MRC, ZRA, Ministry of Finance, AfDB, and the World Bank, implemented under the PBFT partial-synchrony framework. The inclusion of two independent international nodes ensures cryptographic attributability of any sovereign-level collusion attempt.

**Reported constraint count:** 839 non-linear constraints (circom compile, Groth16 target).

## 2. Pre-Audit Hardening — Disclosed Findings & Resolution

We have conducted five rounds of internal adversarial review prior to this engagement, including a structured pre-analysis using Trail of Bits' **Circomspect** static analysis framework (github.com/trailofbits/circomspect). The full pre-analysis document (`Circomspect_Pre_Analysis.md`) is enclosed.

In the interest of efficiency, we disclose that all critical findings identified in our pre-analysis have been fully resolved in circuit v1.1:

- **Royalty Rate Upper Bound (RC-05):** In our pre-analysis (Finding 1), we identified a missing upper bound constraint on `royalty_rate_bps`, which could allow a prover to supply an out-of-bounds rate up to 8,191 bps. We have patched this in `compliance.circom` v1.1 by adding a `LessThan(13)` check (lines 59–63), enforcing that `royalty_rate_bps ≤ 5,000` (the Zambian statutory cap).
- **Intermediate Witness Range Constraints:** `tonnage_t` and `mineral_content_m` now carry independent `Num2Bits(47)` components (lines 76 and 94), in addition to the scaling gate constraints and bounded remainder witnesses.
- **Grade Semantic Bound:** A `LessThan(20)` component (lines 38–41) now enforces `grade_g ≤ 1,000,000` (100% grade ceiling).

While these findings are resolved, we invite your independent confirmation and review of these implementations.

## 3. Requested Audit Scope

We request a full-scope security review covering the following:

1. **Circuit Soundness & Completeness:** Independent verification that the R1CS constraint system is sound (no valid proof for a false statement) and complete (every true statement has a valid proof). Specific focus on under-constrained witness vulnerabilities, including independent confirmation of the patches described in Section 2 above.

2. **Poseidon Implementation Integrity:** Verification that the circomlib Poseidon(2) instantiation correctly implements the algebraic hash specification and that the Truth Anchor binding is cryptographically robust against preimage and second-preimage attacks within the circuit context.

3. **Fixed-Point Arithmetic Correctness:** Formal verification that the scaling gate decomposition faithfully represents the intended fiscal computation for all inputs within the declared valid range, with particular attention to overflow and field-wrap edge cases.

4. **Trusted Setup Considerations:** Guidance on the appropriate Powers of Tau ceremony strategy for production deployment. Specifically: whether the existing Hermez Phase 1 ceremony (ptau file) is sufficient for our constraint count, and what Phase 2 specialisation is required.

5. **BFT Protocol Review:** Assessment of the five-node PBFT implementation against the n=5, f=1 safety and liveness bounds under partial synchrony, with specific attention to the multi-jurisdictional network topology and the cryptographic attributability claim for multi-node collusion scenarios.

6. **Side-Channel & Constant-Time Analysis:** Review of the Prover implementation for timing side-channels that could leak private witness data through proof generation duration or memory access patterns.
